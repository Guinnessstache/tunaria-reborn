# Project Tunaria Reborn

A community server for **EverQuest Online Adventures: Frontiers**, the PlayStation 2
MMO, written from scratch in Python. Point a PS2 or PCSX2 client at it, create a
character and walk into Tunaria.

> For preservation and interoperability on software you own. The game client and
> disc files are not included: you need your own copy of the game. A small amount
> of game data recorded from the Sandstorm server is included so the server works
> out of the box: the network capture in `captures/` and the login-screen pack in
> `eqoa_server/patch_data/`. Keep deployments non-commercial.

## Status

Early but playable to the point of logging in and walking around.

**Working**

- Patching: the client's patch check, hosts file and login-screen pack are
  generated by the server, so no patch files are needed.
- Login, with accounts created automatically on first login. An account's
  password is set by its first login and checked after that (the admin panel
  can reset it, or turn checking off).
- Server list, character list and character creation.
- Entering the world, with reliable delivery (retransmits, acks, keepalives),
  so the session stays up while you play.
- Your own character is visible in the world with its own race, class, model,
  hair and face, starting at its race's (or home city's) starting point.
- Characters start with a stack of their home region's rations and all of
  their class's level 1 abilities plus Return Home (from the Prima guide's
  ability tables). Equipped weapons, shields and armor show on the character,
  and items can be equipped and unequipped in game.
- Characters log back in where they left off.
- A web **admin panel**: start / stop / restart services, players online,
  accounts, MOTD, live log, and one-click updates from GitHub.

**Not yet**

- Game account passwords are not checked (any password logs in).
- Abilities can't be cast yet, and only Warrior, Shadowknight and Return Home
  records are copies of real server data; the others are built from the guide's
  numbers, with icons of the same kind of ability. Stats come from a captured
  template. Weapon and shield models are exact only where known (the Sandstorm
  capture, or picked in the model browser); other weapons get a game model of
  the same shape. Armor appearance needs model data most items don't have.
- No other players, NPCs, combat or quests in the world yet.

## Quick start

You need **Python 3.10+** and **git**. The server has no other required
dependencies.

```powershell
git clone https://github.com/Guinnessstache/tunaria-reborn.git
cd tunaria-reborn
.\start_server.bat --host 0.0.0.0 --public-host 192.168.1.51    # Windows PowerShell
./start_server.sh --host 0.0.0.0 --public-host 192.168.1.51      # Linux / macOS
```

Set `--public-host` to the IP address the game client connects to (this PC's
LAN IP for home play). The launcher scripts restart the server when the admin
panel asks, for example after an update. `python -m eqoa_server` with the same
options also works, without that ability. `python -m eqoa_server --help` lists
every option.

**Client:** a PS2 or PCSX2 running EQOA: Frontiers with a DNAS / DNS patch that
points it at your server; `tools/make_local_pnach.py --ip <your IP>` builds a
PCSX2 patch from the Sandstorm one.

**Linux server:** one command installs it as a service that starts at boot
(Ubuntu / Debian):

```sh
curl -fsSL https://raw.githubusercontent.com/Guinnessstache/tunaria-reborn/main/deploy/install.sh | sudo bash
```

Details and the manual steps: [`docs/linux-server.md`](docs/linux-server.md).

### Ports

| Port | Protocol | Service |
| --- | --- | --- |
| 9735 | TCP | Login |
| 7000 | TCP | Patch files and news (MOTD) |
| 10070 | UDP | Game |
| 8080 | TCP | Status page |
| 8090 | TCP | Admin panel (this PC only, unless `--admin-host 0.0.0.0`) |

## Admin panel

Open <http://localhost:8090/> while the server runs. The first start prints a
generated admin password in the console, and the panel makes you choose your
own at first sign-in. (Or set one with `--admin-password` / `EQOA_ADMIN_PASSWORD`.
Forgot it? Stop the server and delete `data/admin.json`.)

- **Dashboard**: start, stop or restart each service independently, uptime and
  request counts, CPU and memory (with `pip install psutil`), data backup,
  shut down.
- **Players**: live game sessions and their stage; kick a session.
- **Accounts**: accounts and their characters; delete, reset a password or a
  stuck character's position. Set a character's level (optionally learning
  the class's abilities up to it), give it any item (search by name or id),
  equip, unequip or remove items; changes show the next time the character
  enters the world. The **model browser** tries weapon and shield models on a
  character in the world, live, and saves the right one for an item
  (`data/item_models.json`).
- **Settings**: shard name, message of the day, admin password.
- **Logs**: the live server log with a filter.
- **Updates**: see new commits on GitHub, then **Update & restart**. The update
  is fast-forward only, runs the test suite on the new code first, and rolls
  back automatically if the tests fail. Needs the launcher (or the systemd
  service) to restart.

The panel uses plain HTTP. If you open it beyond this PC with
`--admin-host 0.0.0.0`, use a password you don't use anywhere else.

## How it works

One Python process runs four network services, each of which the admin panel
can stop and start on its own:

- **Login** (`eqoa_server/auth.py`): account login and creation.
- **Patch / MOTD** (`eqoa_server/patch_tcp.py`): the client's patch manifest,
  the files it lists, and the news page.
- **Game** (`eqoa_server/game_udp.py`): server list, character select and the
  in-world session over EQOA's reliable UDP protocol.
- **Status** (`eqoa_server/patch_http.py`): a small JSON status page.

Data lives in `data/` (accounts and characters in `server_state.json`, panel
settings, admin password hash); it is git-ignored.

Protocol behaviour is checked against a real server: `captures/from_sandstorm.pcapng`
is traffic from the Sandstorm server, and the server reproduces its world-entry
sequence, reliable-delivery rules and object updates.

## Project layout

```
eqoa_server/       the server, admin panel and updater
eqoa_protocol/     reverse-engineered protocol helpers (control packets)
tests/             test suite (also run by the updater before every update)
docs/              protocol spec, Linux guide, research notes
deploy/            systemd service and its settings file
tools/             capture analysis and PCSX2 patch helpers
captures/          the reference Sandstorm capture
start_server.*     launchers that restart the server on request
```

## Development

```sh
python -m unittest discover -s tests
```

Analyse a capture:

```sh
python tools/decode_pcap.py captures/from_sandstorm.pcapng
python tools/analyze_pcap.py <your.pcapng> --out analysis/summary.json
```

Before committing a capture of your own, strip your login, session keys and
machine details from it:

```sh
python tools/sanitize_capture.py my-capture.pcapng captures/my-capture.pcapng
```

another server package, not redistributable and git-ignored), world entry uses
its bundles. Otherwise it uses the template from the Sandstorm capture.
